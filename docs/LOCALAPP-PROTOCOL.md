# DeskHatch ローカルアプリ連携プロトコル

> DeskHatch の「ドロワー」として組み込める**コンパニオンアプリ**が満たすべき契約。
> この契約を満たすアプリは、DeskHatch 側の**コード変更なし**で、
> `src/renderer/config.js` の `SS_LOCALAPPS` に1項目足すだけで組み込めます。

対象は「自前のデスクトップアプリを DeskHatch のドロワーから開きたい」場合です。
ただの Web サイトなら `type: 'page'` で足ります。

---

## 全体像

```
┌─ DeskHatch ────────────┐        ┌─ コンパニオンアプリ ─────┐
│ ボタン押下              │        │                          │
│   ├ GET /ping ─────────┼───────▶│ {"app":"myapp"}          │
│   │   応答なし          │        │ （未起動）                │
│   ├ exe を detached 起動┼───────▶│ 起動（--background）      │
│   ├ /ping を最大15秒polling      │                          │
│   └ webview に url を表示◀──────┤ http://127.0.0.1:PORT/   │
└────────────────────────┘        └──────────────────────────┘
```

DeskHatch は**ビューアに徹します**。データも状態もコンパニオンアプリ側が持ちます。

---

## アプリ側が満たすこと（必須）

### 1. ループバックで UI を配信する

| 項目 | 要件 |
|---|---|
| バインド先 | **`127.0.0.1` のみ**（`0.0.0.0` にしない。LAN に晒さない） |
| ポート | **固定**。他アプリと衝突しない値を選ぶ |
| 幅 | **360px 程度から崩れない**こと。ドロワーは細い |
| スキーム | `http`（ループバックなので TLS 不要） |

DeskHatch は `127.0.0.1` / `::1` / `localhost` 以外には**接続しません**。
この制限はメインプロセスで強制されており、ドロワー定義では回避できません。

### 2. ヘルスエンドポイントを持つ

```
GET /ping  →  200  {"app": "myapp"}
```

- **認証不要**（ループバックのみなので）
- JSON を返す。`expect` で照合され、**ポートを別プロセスが握っていた場合に誤認しない**ための鍵になります
- 副作用なし。DeskHatch はドロワーを開くたび、起動待ちの間は数百msごとに叩きます

### 3. 「画面を出さずに待機」する起動引数を用意する

```
myapp.exe --background    # サーバだけ起動。自前のウインドウは出さない
myapp.exe                 # 通常起動（自前のウインドウを出す）
```

ドロワーから開く時は前者が使われます。`--background` が無いと、
ドロワーを開くたびにアプリ本体のウインドウも出てきてしまいます。

### 4. 二重起動に耐える

DeskHatch は「ヘルスチェックに応答が無い」と判断したら起動を試みます。
競合状態で二重に起動されうるので、**2つ目のプロセスは即座に終了する**か、
既存プロセスに処理を委ねてください。

### 5. 終了させられない前提で動く

DeskHatch は起動したプロセスを **detached** で切り離します。

- ドロワーを閉じても**止めません**
- DeskHatch を終了しても**止めません**

アプリ自身のライフサイクル（タスクトレイに常駐する等）は、アプリ側の責任です。

## アプリ側が満たすこと（任意）

### アクションエンドポイント

ボタンの右クリックメニューに項目を足せます。

```
GET /show  →  自前のウインドウを前面に出す（副作用は表示のみ）
```

`GET` 1発で完結する副作用に限ります。認証不要・引数なし。

### 重い処理は自前のウインドウで

ドロワーは細くて小さいので、**本格的な作業画面はアプリ本体の別ウインドウ**で
開くのが自然です。DSBooks は「ドロワーで本を選ぶ → 本体が別ウインドウで開く」
という形を取っています。DeskHatch 側の対応は不要です。

### 保存領域

ドロワーの webview は `persist:localapp-<id>` という**専用パーティション**です。
アプリ本体の保存領域とは別物なので、**状態は webview 側に持たせない**でください。
本棚・読書位置・設定などはアプリ本体が持ち、ループバック越しに配信します。

## DeskHatch 側の登録

`src/renderer/config.js` の `window.SS_LOCALAPPS` に追加します。
既定のボタン一覧には入りません。ユーザーが
**☰ → 設定 → 「＋ 項目を追加」**（またはボタン右クリック →「新規項目を追加」）
から選んで追加します。

```js
{
  id: 'dsbooks',                       // 一意。webview partition 名にも使われる
  label: L('本棚'), icon: '📚',
  type: 'localapp',
  width: 520,

  url: 'http://127.0.0.1:47817/',      // ループバックのみ
  health: '/ping',                     // url からの相対で解決
  expect: { app: 'dsbooks' },          // ヘルス JSON がこの部分集合を満たすこと

  launch: {
    win32: { exe: '%LOCALAPPDATA%\\Programs\\DSBooks\\DSBooks.exe',
             args: ['--background'] },
    // darwin: { exe: '/Applications/DSBooks.app/Contents/MacOS/DSBooks', args: [...] },
  },

  actions: [                           // 右クリックメニューに追加される
    { label: L('本棚ウインドウを開く'), get: '/show', launchArgs: [] },
    { label: L('表紙キャッシュ作成ツール'), launchArgs: ['--library-tools'] },
  ],

  platforms: ['win32'],                // 省略時はどのOSでも表示
  download: 'https://example.com/dl',  // exe が見つからない時の案内先（任意）
}
```

### フィールド一覧

| フィールド | 必須 | 内容 |
|---|---|---|
| `id` | ✅ | 一意の識別子。`persist:localapp-<id>` になる |
| `type` | ✅ | `'localapp'` 固定 |
| `url` | ✅ | 埋め込む UI。**ループバックのみ** |
| `health` | ✅ | ヘルスエンドポイント。`url` からの相対可 |
| `expect` | 推奨 | ヘルス JSON が満たすべき部分集合。省略すると 2xx なら何でも通る |
| `launch` | ✅ | プラットフォーム別 `{exe, args}`。キーは `win32`/`win`、`darwin`/`mac`、`linux` |
| `actions` | | 右クリック項目。`get`（ループバックGET）と `launchArgs`（引数付き起動）。両方ある場合、起動中なら `get`、未起動なら起動 |
| `platforms` | | 表示対象OS。省略で全OS |
| `download` | | exe 不在時に開く案内ページ |
| `label` `icon` `width` | | 見た目 |

`exe` の `%VAR%` は展開されます（Windows 流に大文字小文字を無視）。
先頭の `~/` も展開されます。

## 動作仕様

### ドロワーを開いた時

1. `health` を確認。応答し `expect` を満たせば → **UI を表示**
2. 応答しない場合:
   - `launch` にこのOS用の定義が無い → 「このOSでは利用できません」
   - exe が見つからない → 「見つかりません」＋**場所を指定**／ダウンロード／再試行
   - exe がある → **detached で起動**し、「起動しています…」を出しながら
     `health` を**最大15秒ポーリング**（最初は150ms間隔、徐々に1秒間隔へ）
3. 時間内に応答しなければ「応答しません」＋再試行

「場所を指定」で選んだパスは `ss.localapp.exe` に保存され、
以後そのドロワーの既定パスより優先されます。

### 外部リンク

`url` と**同一オリジン以外への遷移**は、ドロワーを連れていかずに
**標準ブラウザで開き**ます。

## セキュリティ境界

ドロワー定義は「ユーザーが持ち込んだデータ」なので、2点をメインプロセスで強制しています。

**1. HTTP はループバック限定**
`127.0.0.1` / `::1` / `localhost` のみ。これが無いと、ドロワー定義が
「そのPCから到達できる任意のホストを DeskHatch に叩かせる」SSRF の入口になります。
`localhost.evil.com` のような引っかけも弾きます。

**2. 起動はシェルを経由しない**
`spawn(exe, argv, {shell:false})` のみ。パスも引数も**シェルに渡りません**。
さらに「実在するファイルであること」を確認してからしか起動しません。
これは `src/main/system.js` の「renderer から任意コマンドを実行させない」方針と同じです。

ヘルス応答は 64KB で打ち切ります（暴走したローカルサーバ対策）。

## 実装の在りか

| ファイル | 役割 |
|---|---|
| `src/renderer/lib/localapp.js` | 純粋ロジック（ループバック判定・`%VAR%` 展開・`expect` 照合・状態遷移・ポーリング間隔） |
| `src/main/localapp.js` | ループバック GET・exe 解決・detached 起動・ファイル選択ダイアログ |
| `src/preload/preload.js` | `window.localapp` ブリッジ |
| `src/renderer/renderer.js` | `buildLocalApp()`／`runLocalAppAction()`／プリセット追加フロー |
| `src/renderer/config.js` | `SS_LOCALAPPS` プリセット定義 |
| `tests/localapp.test.js` | 純粋ロジックのテスト |
| `tests/localapp-main.test.js` | スタブサーバーを立てた結合テスト |

---

## 新しいアプリを足す手順

1. アプリ側で「必須」4点を実装する（ループバック配信・`/ping`・`--background`・二重起動耐性）
2. `src/renderer/config.js` の `SS_LOCALAPPS` に1項目追加する
3. 終わり

コードは変更不要です。変更が必要になったら、それは**プロトコルを拡張すべき**という
サインなので、この文書も併せて更新してください。
